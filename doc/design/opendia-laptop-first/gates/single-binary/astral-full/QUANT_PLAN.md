Area is the emitted peak area, not a calibrated concentration. `sequence` is library sequence and can be modification-bearing (`OpenDIALibrary.cpp` selects modified sequence when supplied). ## Frozen computations

- Keep nondecoy targets at tool run q cutoffs **0.005, 0.01 and 0.02**, reporting every cutoff without choosing the most favorable. No global-q requirement or entrapment-derived threshold. Report `--population all` and `--population human` separately with `--library search6.pqp`. The latter is a post-search grading stratum excluding any target with any protein accession containing literal `_p_target`, not authenticated species inference and it can include contaminants. Missing protein mappings or unknown accepted target IDs fail population grading. Report excluded counts. Labels never feed scoring, q calibration, search filtering, or choices of normalization method. Each stratum's fixed descriptive normalization below is fit independently and must be labeled accordingly. Neither stratum may replace the other or be selected after seeing results.
- Precursor identity is exact library `precursor_id`, validated for sequence/charge consistency among accepted rows. All outputs must share the same frozen library. Peptide identity is exact `sequence`, collapsing charge states by summing positive accepted precursor areas. This is a descriptive modified-peptide area proxy, not peptide-level FDR control. Charge-state detection changes can change its sum. No stripping modifications, protein inference, shared-peptide allocation, or protein rollup.
- Report precursor and peptide pairwise intersection, union, Jaccard, and detection completeness (1/3, 2/3, 3/3) for each seed. Also report positive-area completeness, including zero-positive features. Universe is the observed accepted union, **not** all library precursors. Absent, rejected, zero, negative, and nonfinite areas are not imputed. Accepted zero/nonfinite rows still count as detections, but are null for intensity analyses. Separate audit counts distinguish accepted nonpositive/nonfinite areas from q rejection. Missingness is not evidence of absence from the sample.
- Three-raw CV is sample SD (`ddof=1`) divided by arithmetic mean on positive 3/3 features only, per score seed. Emit per-feature CVs as fractions, not percentages. Report raw and explicitly median-normalized CV side by side, never normalized alone. Normalization uses each run's median log2 area on that comparison's common positive complete set, subtracting its difference from the median of run medians. Archive those log2 offsets and common-set size. No complete set means no normalized values/CVs. This assumption removes a global scale difference and can conceal real loading differences. It is not evidence of accuracy.
- Pairwise Pearson correlation of log2 positive areas uses each pair's positive intersection, with its sample size. Undefined constant/singleton/empty cases are JSON null. Multiplicative median normalization adds a constant in log2 space, so its Pearson correlation is mathematically unchanged from raw log2 Pearson. No pseudocount or log-zero conversion.
- JSON per-feature `positive`, `detected`, raw values, normalized values, and observed median log2 area permit intensity-versus-missingness tables/plots. Show positive-count strata and observed median log2 distributions jointly, including all-null counts. Observed-only intensity is conditional and cannot estimate the unknown abundance of missing features. Complete-case CV and pairwise correlations preferentially retain strong detected signals and can look good despite poor coverage. Report them alongside overlap/completeness, not as standalone quality gates.
- `across_raws` contains separate three-raw analyses for each seed. `within_raw_seeds` contains five-score-seed analyses separately for each raw, including CV, overlap and completeness using the same definitions. These quantify algorithmic sensitivity on the **same acquisition**, not within-injection experimental precision and not biological replication. No pooling 15 files as 15 replicates, no seed-based confidence interval for biological precision, and no best-seed selection. There is no within-run experimental CV available from one acquisition per raw. Summarize every seed's three-raw result, with ranges across seeds if needed, without treating seeds as independent samples.

## Library preparation interface

After the parent plan is frozen and pushed, prepare copies of the full20 PQP produced by CPU `OpenSwathDecoyGenerator -predict_decoys -predict_keep_short` from GPU DIALibGen targets. Do not use DIALibGen copied decoys. No library processing has been run on real data during implementation.

```bash
python3 prepare_library.py full20_predicted_own_decoys.pqp --search6 search6.pqp --scoring12 scoring12.pqp > library_audit.json
```

Both output paths must be new and different from the source. The script opens the source read-only, uses SQLite backup, retains top6/top12 transitions per precursor by descending library intensity with numeric source-ID tie breaking, and reindexes output transition IDs in that order. It updates every table's `TRANSITION_ID` references, retains all precursor IDs and peptide/protein metadata, including short and zero-transition precursors, and verifies source SHA256 did not change. Shared transition mappings are unsupported and rejected. This is a structural transformation, not decoy prediction or pairing repair. Orphan pairs and sibling-count imbalances are reported, never filtered. Output JSON reports target/decoy precursor counts, zero/min/max fragments, own-pair and sibling imbalance, structural entrapment ratio using the literal `_p_target` marker, source numeric-ID/intensity-order violations, and file hashes. The script does not attest generator provenance, which must be archived separately. Failed preparation may leave newly created partial outputs, which must not be used.

`OpenDIAWorkflow.cpp` sorts scoring fragments by numeric transition ID before taking up to 12, so pointing at an arbitrary full20 file is not guaranteed to score its top12 intensities. Use the explicit `scoring12.pqp` companion. Search6 is an identical transition-row subset of scoring12, with the same reindexed numeric transition IDs. Zero-transition precursors remain in PQP but the current transition-join loader may not load them into OpenDIA. Preparation is disk-heavy (two full SQLite backups plus temporary ranking and retained free pages), with no demonstrated full-scale runtime or disk bound. Reserve ample scratch space and record actual preparation resources separately from run budgets.

## Reporting and limits

This is descriptive, with no invented pass threshold for CV or correlation. Publish coverage and unnormalized dispersion even if normalization improves it. If sample metadata confirms identical technical material, describe repeatability, not quantitative accuracy. Without known abundance truth, neither agreement nor entrapment calibration validates area accuracy. Entrapment grading is handled by the parent identification evaluator. Quantification adds no hidden species-label optimization. Outputs do not support protein-level claims.

Synthetic tests cover both population switches and the frozen cutoff grid, scale-only normalization, exact sample CV, missing and nonpositive areas, NaN, q filtering, decoy exclusion, constant/singleton/empty correlations, missing complete sets, charge aggregation, balanced seed grouping, duplicate targets and wrong-schema rejection. Preparation tests invoke its CLI on synthetic PQP and verify tie breaking, top6/top12 intensity order, metadata preservation, identical companion transition subsets, zero/short precursor preservation, structural imbalance counts, excess-fragment rejection and source immutability.
